# Signed native authority snapshot

`POST /recovery-export` exports a bounded, atomic native SQLite capture of control, prepared generations, command results, audit records and the complete outbox, including pending/exported flags. It requires a dedicated dataset-scoped `recovery-export` capability in LIVE mode. Ordinary publication exporters and source feed actors cannot use it. Export never changes control state, executes commands, or writes/deletes R2 objects.

The existing registered receipt signer signs a versioned manifest containing the authority locator, public trust configuration, captured watermark, coverage, row counts and hashes of compressed pages. An independent verifier requires separately supplied trusted authority configuration; trust embedded in a backup is insufficient. It verifies signatures, codec bounds, generation digests, active receipt, corresponding commit commands/audit, and the latest control audit. Snapshot capture is a synchronous SQLite transaction; subsequent signing can run while newer commits proceed without altering the captured watermark.

Limits are explicit: 4,096 rows across the four tables, 8 MiB aggregate data, 128 pages, and 400,000 decoded bytes per page/row budget. Oversized captures fail closed without truncation. This bounded route needs pagination or a separately designed larger export before large retained histories can be exported. No new actor or capability has been provisioned on the deployed Cloudflare feed.

Run `node scripts/rehearse-authority-snapshot.js`. The harness exports actual Miniflare native state, disposes its source and starts a separate verifier process using serialized snapshot bytes and an independent trust file. Run `node scripts/verify-authority-snapshot.js SNAPSHOT TRUST [RESULT]` to reopen an existing snapshot. CI preserves the snapshot, public trust and verification result. The fixture signer is ephemeral and its private key is never saved.

This closes an authenticity gap for native control/audit in the local recovery prerequisite. Existing publication-backup verification remains unchanged. Coverage explicitly excludes external artifacts, scheduler state, deployment code and storage credentials. It proves neither cloud restoration, independent/offsite storage, RPO/RTO, revoked old credentials, a new generation, nor safe writer resume. It is not a restore endpoint. G1 and whole Core 2.0 production readiness remain incomplete.

Next recovery work: isolated cloud capture/readback; full artifact/config coverage; restore under a separately authorized locator and new generation; actual old command and storage credentials denied with 401/403 while replacement credentials work; epoch high-watermark checks; expired override and notification suppression; measured RPO/RTO and restart/rollback proof before resuming writers.
