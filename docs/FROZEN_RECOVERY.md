# Frozen native recovery bootstrap

`POST /recovery-bootstrap` installs a verified recovery anchor into a fresh, empty native SQLite authority. It requires a dedicated LIVE `recovery-bootstrap` capability and a dataset-specific `RECOVERY_PLANS_JSON` deployment pin. The request is `{}`. Source trust, exact canonical snapshot digest, archive key, target trust hash, owner and old epoch high-watermark come from the plan, never from request claims or backup-supplied trust.

The source is the signed native snapshot described in [AUTHORITY_SNAPSHOT.md](AUTHORITY_SNAPSHOT.md). Only a bounded `recovery/snapshots/<name>.json` R2 object is read. Signature, page bounds, generation hashes, command/audit links and complete publication/control history are verified before mutation. Environment and dataset must match. The target requires a fresh native object name/id and authority instance, a new recovery generation, explicit locator version/hash migration, new P-256 signing keys and no approved positive decision types. Its configured private signer must match the new public trust.

The transaction checks that native state and all four tables are empty. It installs a frozen state with epoch above the separately pinned high-watermark, revision/control revision zero and no active receipt. A recovery audit references the immutable digest and source watermark. Historical commands, prepared/outbox records, active receipts and overrides remain archived in the source snapshot; they are never installed into executable tables or dispatched. The old watermark is lineage, not a restored current publication watermark. Concurrent or repeated restore cannot replace the first installed state.

Normal bootstrap cannot bypass a configured recovery plan. Normal publication is frozen, positive policies are empty, and ordinary FREEZE=false is denied while `writer_resume_allowed` is false. There is no activation/resume endpoint in this change. Explicit ABSTAIN retraction remains available while frozen. A transfer does not remove the recovery gate. No cloud plan, actor or deployment is provisioned by merging this source change.

Run `node scripts/rehearse-frozen-recovery.js`. Actual Miniflare SQLite/R2 exports a signed source history and installs the new authority. An old command token is revoked and probed on its original native route (401) with a live read witness (200); the same old token is denied on the replacement route. The replacement process is disposed and recreated using persisted SQLite/R2, then exact state and a changed incarnation are checked. A signed target export shows one recovery audit and empty executable command/outbox tables. Private keys and tokens are not saved in evidence.

Tests also cover corrupt archives, target pins, generation/native/locator/key/epoch constraints, positive policy denial, concurrent restore, blocked unfreeze, rejected normal commit and a foreign old checkpoint. Publication export refuses to overwrite the foreign checkpoint; after removing only injected local test corruption, an explicit retraction publishes under the new signer/generation with an ABSTAIN decision and REVOKED serving eligibility.

Scope is `LOCAL_FROZEN_NATIVE_RECOVERY`. Local bootstrap and restart timings are measurements of a fixture, not cloud RPO/RTO or SLA. This is not a full system restore and does not prove cloud command/storage write credential revocation, external artifact coverage, offsite storage, source recollection or consumer cutover. G1 and production readiness remain incomplete. The next drill must use separate isolated cloud authorities, actual old endpoint and disposable storage-write deny probes with working witnesses, verified artifact/config coverage and measured recovery observations. The healthy reference feed must retain its existing locator, actors and schedule.
